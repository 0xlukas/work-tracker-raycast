# Work Tracker for Raycast: project rules

## Never touch WorkTracker's data directly

WorkTracker's store (`~/Library/Application Support/WorkTracker/WorkTracker.store`) holds the user's real hours and syncs to their other Macs. Never open it, with `sqlite3` or anything else, and never write to WorkTracker's preferences (`com.worktracker.app`) or its sync folder.

- Every read and write goes through WorkTracker's MCP server (`src/lib/mcp.ts`, tools in `src/lib/api.ts`). Its tools are in the WorkTracker repo, `WorkTracker/Sources/Assistant/AssistantTools.swift`; the README there has the list.
- Reading the server's port and key with `defaults read com.worktracker.app …` is fine. Turning the server on is the user's step (Settings › Assistants); never do it for them.
- Use the app's numbers (`get_overview`, `get_summary`, `get_vacation`, …). Don't recompute balances, holidays or vacation here: the app's calculator knows schedule changes, absence categories and carry-over.
- If a feature needs something no tool offers, the tool belongs in WorkTracker, not a workaround here.

## Testing

Never test against the real WorkTracker. Its server is on port 47615; the live tests refuse that port and its key.

Test build (its own data folder, preferences and sync folder):

```sh
git -C ~/code/personal/work-tracker worktree add --detach <folder outside the checkout> origin/main
cd <folder> && BUNDLE_ID=com.worktracker.app.test scripts/build-app.sh <folder>/.build/testapp
defaults write com.worktracker.app.test assistantServerPort -int 47616
defaults write com.worktracker.app.test assistantServerEnabled -bool true
open <folder>/.build/testapp/WorkTracker.app        # creates its key
WORKTRACKER_TEST_PORT=47616 WORKTRACKER_TEST_KEY=$(defaults read com.worktracker.app.test assistantServerToken) npm test
```

Add made-up data to the test build through its MCP server (projects, entries, absences, calls). The live tests need at least one project and clean up what they add. Quit the test app and `git worktree remove` the folder afterwards.

To try the commands in Raycast against the test build, set the extension's **Assistant Key** and **Port** preferences to the test build's, and clear them afterwards.

## Building

- `npm run build` builds into `dist/`. Don't run `ray build` without `-o`: it writes into `~/.config/raycast/extensions/`, which installs the extension into Raycast.
- `npm run dev` (`ray develop`) imports the extension into Raycast and keeps running. Only run it when the user asks to install; never in a way that waits forever.
- Keep `npm run build`, `npm run lint` and `npm test` clean.

## Conventions

- Days are `YYYY-MM-DD` and times `HH:MM` in Zurich time, as the tools take them (`src/lib/format.ts`). A date picker's `Date` is the Mac's local day.
- Show WorkTracker's own error messages: they're written for people.
- Destructive actions confirm first and say the change syncs; additions offer **Undo** in their toast.
- Keep command names (`view-today`, `add-entry`, `daily-quote`, …) stable: Raycast keys hotkeys and aliases by them.
- `src/lib/quotes.json` is generated by `npm run sync-quotes` from WorkTracker's `DailyQuote.swift`; run it when the app's quotes change. `quoteIndex` mirrors the app's choice of quote (it changes at 1 am Zurich time).
- When WorkTracker's tools change, update `src/lib/types.ts`, `api.ts`, the README's tool list and the live tests.
